# Manual retrieval: review and acceptance

The first patch is developed from supplied release `2026.11.10` (`07ff2e6`). It
does not change the embedding model, Qdrant collection, originals, inventory
records, maintenance schedules or database schema. Later roadmap phases remain
backlog.

## Release-baseline validation

Node 26.13.0 / pnpm 10.28.0: type checks and the full web/docs/server build pass.
The full suite reports **438 passed, 7 failed, 5 skipped**. All **37 added
regressions pass**. Failure-name comparison against the unmodified release found
no new failures: six Windows libSQL backup/snapshot cleanup failures and one Unix
file-mode assertion on Windows remain. The lockfile is unchanged. These results
do not establish that the Linux/container or newer-main integration suite passes.

## What changed

- `document-passages.ts` selects original Markdown sections by heading and body
  relevance, with conservative operation aliases. It retains numbered children,
  associated warnings and preparations, multiple requested passages, and source
  order. Headingless/OCR fallback groups sequential instructions and intervening
  text. Context omissions are explicit.
- `ask.ts` ranks document evidence before budgeting it, keeps short factual
  documents readable, verifies household ownership and scopes duplicate-topic
  coverage to each item. It distinguishes procedural intent from factual mentions
  of cleaning or descaling.
- Ask reserves input/output space through `ASK_CONTEXT_TOKENS`, defaults to a
  4096-token client budget, and passes an explicit output ceiling. Oversized
  procedures are refused with attachment links. Input counts are estimates.
- Procedural replies must cite every selected required document and retain at
  least the source's numbered-step count. Explicit source warnings are quoted
  verbatim when missing from a generated reply. Missing extracted button symbols
  receive an original-illustration notice. These structural checks do not prove
  semantic faithfulness or extraction completeness.
- Attachment citations include retrieved section headings. No PDF pages are
  invented. The interface preserves newlines as safe plain text.

The patch also adds development/staging documentation, local-data exclusions,
an optional digest-pinned Docker base argument and a fork image-publishing guard.
See [upstream maintenance](../UPSTREAM.md) and
[isolated build/staging instructions](development-testing.md).

## Live synthetic evidence

The opt-in evaluator uses a fictional paper exercise, including a late twelve-step
section, safety warning, rinse/cleanup steps and a deliberately missing button
symbol. The manual exceeds 50,000 characters. The second version of the question
explicitly asks about the simulated exercise so it cannot be mistaken for a
request to use these fictional instructions on a real appliance.

[Recorded final answers and measurements](evidence/synthetic-answer-evaluation.json)
were generated by the existing `frob/qwen3.5-instruct:4b` model. All three cases
passed: complete procedure, unsupported-question refusal and embedded-instruction
rejection. Procedural requests used a 1536-token output ceiling within the
4096-token client budget; both completed normally in about ten seconds. The
report contains synthetic text only and omits the private endpoint.

To repeat using a model endpoint you choose:

```bash
pnpm --filter @ferret/server exec tsx eval/ask.ts \
  --url http://YOUR_MODEL_HOST:PORT --model YOUR_MODEL --context 4096
```

The script requires explicit endpoint/model flags, makes three real requests and
does not load `.env`, use a database, access inventory or alter model settings.
Keep a raw local report outside Git because it includes the endpoint you supply.
It does not establish performance on other models or prove the De'Longhi manual
was extracted correctly.

## Test a private copy of the De'Longhi manual

1. Use the feature branch's image and the isolated staging setup in
   [development-testing.md](development-testing.md). Use a fresh database, storage,
   secrets, container name and port. Leave Qdrant disabled for the initial
   keyword-only check; if enabled later, use a new staging collection.
2. Configure the existing working vision/text model and Docling endpoint in the
   staging environment only. Keep their service settings unchanged. Upload a
   private copy of the English manual to a disposable staging item and wait for
   conversion/analysis. Preserve the original PDF. Do not apply maintenance
   suggestions as part of this test; their reliability is a later phase.
3. Ask **“How do I descale my De'Longhi?”** and **“How do I remove scale?”**.
   Compare the answer against Section 11 in the original PDF. Check every one of
   the twelve steps, preparations, safety warnings and final rinsing/cleanup.
   Open the attachment citation and check its section label. A retrieved section
   alone is not a passing answer.
4. Check every button/figure reference against the PDF. Where extracted symbols
   are absent, the answer must direct the reader to the original illustration
   rather than name a guessed button. No line number may become a PDF page.
5. Ask about cleaning two distinct components, an unrelated cable attribute,
   warranty coverage and a small receipt. An unsupported question must be refused;
   unrelated questions must not return the descale procedure.
6. Create a second disposable household without this manual. Repeat the manual
   question and confirm that no first-household document or citation appears.
7. Record the source/image SHA, lockfile hash, base-image digest, model/context,
   latency, final answers and human completeness review. Keep the real manual and
   resulting private answers outside Git. Confirm original attachment bytes and
   inventory fields remain unchanged.

The actual De'Longhi PDF/Docling Markdown was not among the supplied source
files, so its final-answer acceptance remains outstanding. Docker was unavailable
locally; no container has been built or deployed. The newer fork `main` also needs
its own integration checks before an integrated image can be accepted.

## Remaining limits

Heading/OCR selection is heuristic. Safety text with no identifiable label or
structure can still be missed, and a later instruction separated by a large or
ambiguous OCR gap may need the original PDF. Same-operation phases spread across
different attachments may look like duplicate manuals. Search must first find
the item; vector thresholds and the existing indexing chunk cap are unchanged.
Section labels describe retrieved context, not independent verification that a
model used every line. Step counts cannot detect a changed meaning or reordered
paraphrase. Human review of the real manual is still required before deployment.
